# ProofWaiver — Increment 1

**FICTIONAL DEMO — NO REAL HIRING**

This is a simulation-only employer accountability tool. No real employers, applicants, hiring decisions, or audits are represented. Browser localStorage is editable and is **not** a tamper-proof audit trail.

## Setup

Requires Node.js 20.19+ or 22.12+ and npm.

```bash
npm install
npm run dev
```

Open the local URL printed by Vite. Test with `npm test`; check the production bundle with `npm run build`.

The four screens are placeholders in this increment. Storage and schemas are functional, but approval, eligibility, LLM advisory, final waiver decisions, and dashboard calculations are **not** implemented. No real personal data should be entered.

Keep the approved locked `docs/PACKET.md` unchanged. If you have the existing `docs/assets/proofwaiver-mockup.png`, keep it there as a design reference; neither is regenerated by this increment.


## Increment 1 acceptance-test mapping (partial only)

- **T01 — Required agreement fields:** Partially supported by strict schema and validation foundations. Full submission, approval and activation checks belong to Increment 2.
- **T12 — Disallowed candidate information:** Partially supported by record-field allowlists and rejection of unsupported fields (including candidate-score fields). The no-forwarding-to-LLM portion cannot be tested before Increment 4.
- **T17 — Mobile usability:** Only the responsive four-screen shell can be checked in Increment 1. Full usability across all four completed workflows cannot be accepted until later increments.

These are incremental checks, **not** claims that T01, T12 or T17 pass in full. Browser/manual checks and local test outcomes must be recorded after actual execution.
